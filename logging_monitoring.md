# Логирование и Мониторинг

## Конфигурация Логирования

Приложение использует встроенный модуль логирования Python со структурированным логированием для всестороннего мониторинга.

### Уровни Логов

- **DEBUG**: Детальная информация для отладки
- **INFO**: Общая информация о работе приложения
- **WARNING**: Предупреждающие сообщения о потенциальных проблемах
- **ERROR**: Сообщения об ошибках
- **CRITICAL**: Критические ошибки, требующие немедленного внимания

### Формат Логов

```
%(asctime)s - %(name)s - %(levelname)s - %(message)s
```

Пример:
```
2024-01-15 10:30:45,123 - module_content - INFO - Контент сгенерирован успешно
```

### Файлы Логов

- **bot.log**: Основной лог приложения
- **error.log**: Лог только с ошибками для быстрой идентификации проблем
- **content.log**: Специфические логи генерации контента

## Возможности Мониторинга

### Проверки Здоровья

Приложение включает встроенный мониторинг здоровья:

1. **Подключение к API**: Регулярные проверки API Telegram, OpenAI и Telega.in
2. **Статус Планировщика**: Мониторинг запланированных заданий
3. **Использование Ресурсов**: Мониторинг памяти и дискового пространства
4. **Генерация Контента**: Уровни успеха/неудачи

### Уведомления Администратора

Критические события отправляются в Telegram чат администратора:

- **Запуск/остановка системы**
- **Сбои API**
- **Неудачи генерации контента**
- **Ошибки публикации**
- **Высокие уровни ошибок**

### Сбор Метрик

Приложение отслеживает:

- **Генерация Контента**: Уровень успеха, среднее время
- **Публикация**: Уровень успеха, количество повторных попыток
- **Интеграция Рекламы**: Доступные объявления, отслеживание доходов
- **Использование API**: Количество запросов, уровни ошибок

## Обработка Ошибок

### Логика Повторов

- **Вызовы API**: Экспоненциальная задержка (5с, 10с, 20с)
- **Публикация**: До 3 попыток повтора
- **Генерация Контента**: Запасной вариант с кэшированным контентом

### Классификация Ошибок

- **Восстановимые**: Таймауты сети, ограничения скорости
- **Невосстановимые**: Недействительные API ключи, недостаточные разрешения
- **Критические**: Сбои системы, повреждение данных

### Восстановление после Ошибок

- **Автоматическое**: Повтор с задержкой
- **Ручное**: Уведомление администратора для вмешательства
- **Запасной вариант**: Использование кэшированного/стандартного контента

## Настройка Мониторинга

### Локальный Мониторинг

```bash
# Проверка логов
tail -f logs/bot.log

# Мониторинг ошибок
tail -f logs/error.log

# Проверка системных ресурсов
top -p $(pgrep -f main.py)
```

### Мониторинг Docker

```bash
# Просмотр логов
docker logs -f health-bot

# Проверка статуса контейнера
docker ps | grep health-bot

# Мониторинг ресурсов
docker stats health-bot
```

### Анализ Логов

#### Распространенные Паттерны Ошибок

1. **Ошибки Telegram API**
   ```
   ERROR - Ошибка Telegram API: BadRequest
   ```
   - Проверьте токен бота и разрешения

2. **Ошибки OpenAI API**
   ```
   ERROR - Не удалось сгенерировать текстовый контент
   ```
   - Проверьте API ключ и кредиты

3. **Ошибки Ads API**
   ```
   ERROR - Не удалось получить рекламу
   ```
   - Проверьте учетные данные Telega.in

#### Мониторинг Производительности

```bash
# Время генерации контента
grep "Контент сгенерирован" logs/bot.log | tail -10

# Уровень успеха публикации
grep "опубликовано успешно" logs/bot.log | wc -l

# Количество ошибок
grep "ERROR" logs/error.log | wc -l
```

## Оповещения

### Оповещения в Чат Администратора

Бот отправляет уведомления для:

- **Запуск**: "🤖 Бот запущен успешно"
- **Ошибки**: "❌ Публикация не удалась: [детали ошибки]"
- **Предупреждения**: "⚠️ Обнаружено высокое количество повторных попыток"
- **Успех**: "✅ Контент опубликован успешно"

### Оповещения на Основе Логов

Настройте внешний мониторинг:

```bash
# Проверка критических ошибок
if grep -q "CRITICAL" logs/error.log; then
    echo "Обнаружена критическая ошибка"
    # Отправить оповещение
fi
```

## Руководство по Устранению Неисправностей

### Высокие Уровни Ошибок

1. Проверьте страницы статуса API
2. Верифицируйте учетные данные
3. Просмотрите ограничения скорости
4. Проверьте сетевое подключение

### Неудачи Публикации

1. Верифицируйте разрешения бота
2. Проверьте ID канала
3. Протестируйте ручную публикацию
4. Просмотрите логи ошибок

### Проблемы Генерации Контента

1. Проверьте статус OpenAI API
2. Верифицируйте API ключ
3. Протестируйте с простыми подсказками
4. Проверьте лимиты токенов

### Проблемы с Памятью

1. Мониторьте использование памяти
2. Очистите временные файлы
3. Перезапустите при необходимости
4. Оптимизируйте обработку видео

## Резервное Копирование и Восстановление

### Резервное Копирование Логов

```bash
# Ежедневное резервное копирование логов
tar -czf logs_$(date +%Y%m%d).tar.gz logs/
```

### Резервное Копирование Конфигурации

```bash
# Резервное копирование файла окружения
cp .env .env.backup
```

### Процедуры Восстановления

1. **Перезапуск Сервиса**: `docker restart health-bot`
2. **Полный Перезапуск**: Остановить, сделать резервную копию логов, чистый запуск
3. **Восстановление Данных**: Восстановить из резервных копий при необходимости
